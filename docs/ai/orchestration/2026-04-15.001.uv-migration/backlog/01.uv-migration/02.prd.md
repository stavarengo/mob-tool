# PRD: Migrate mob-tool to UV

**Project:** mob-tool
**Branch:**

## 1. Introduction/Overview

mob-tool currently uses the legacy pip/venv/setuptools workflow for local development and pip/build/twine for CI publishing. This migration replaces all of that with UV as the single frontend tool, while keeping setuptools as the build backend. The result is faster installs, a committed lockfile for reproducibility, and a single tool for both local dev and CI.

## 2. Goals

- Replace the pip/venv local development workflow with `uv sync` / `uv run`.
- Replace the pip/build/twine CI publishing workflow with `uv build` / `uv publish`.
- Commit a `uv.lock` file for reproducible dependency resolution.
- Pin the project Python version via `.python-version` file.
- Remove the dead `setup.py` shim.
- Update README to reflect the new UV-based workflow.

## 4. Functional Requirements

- **FR-001:** The `[build-system]` section in `pyproject.toml` must remain unchanged. UV is a frontend; setuptools stays as the backend.
- **FR-002:** The `pyproject.toml` `[project]` metadata, dependencies, and entry points must not be modified.
- **FR-003:** The `.python-version` file must contain exactly `3.11` (matching `requires-python = ">=3.11"`).
- **FR-004:** The `uv.lock` file must be generated by running `uv sync` and committed to version control.
- **FR-005:** The CI workflow must use `UV_PUBLISH_TOKEN` or `--token` to pass the existing `secrets.PYPI_PASSWORD` to `uv publish`.

## 5. Non-Goals

- Changing dependency version specifiers in `pyproject.toml` (e.g., `==` to `>=`).
- Adding `[tool.uv]` configuration or `uv.toml`.
- Upgrading the pinned Python version beyond 3.11.
- Adding dev dependencies or dependency groups.
- Changing the CI trigger logic.
- Adding new CI jobs (linting, testing, type checking).
- Migrating away from setuptools as the build backend.
- Updating GitHub Actions versions (checkout, etc.) beyond what the UV migration requires.

## 6. Technical Considerations

- **UV installs Python automatically.** When `.python-version` is present, `uv sync` downloads and manages the specified Python version. The CI workflow does not need a separate `setup-python` step.
- **`uv sync` creates an editable install.** It replaces both `python -m venv` and `pip install -e .` in a single command.
- **`uv.lock` is cross-platform.** It should be committed. It will be large relative to the project but this is expected.
- **PyPI token format.** `uv publish` accepts the same `__token__`-prefixed API tokens that twine uses. The existing `secrets.PYPI_PASSWORD` secret works without changes.
- **Backward compatibility.** Since `pyproject.toml` and setuptools remain unchanged, `pip install -e .` still works for developers who haven't adopted UV. The README should recommend UV but the old path isn't broken.
- **`.gitignore` edit.** Remove only the `.python-version` line (line 85). Keep the `# pyenv` comment or remove it -- either is fine since it no longer has an associated entry.

## 7. Success Metrics

- `uv sync` succeeds in a clean clone of the repo.

- `uv build` produces dist artifacts (sdist + wheel).
- The CI workflow YAML passes schema validation.
- `setup.py` no longer exists.
- `uv.lock` and `.python-version` are committed.
